# 原声脚本与粗剪标准

## 1. 脚本生成

未指定数量时输出 4 条：

- 2 条营销导向：通过问题紧迫性、价值判断、信任或解决方向形成转化意愿。
- 2 条内容导向：以完整观点或情绪共鸣为目标，不出现购买暗示。

营销导向不等于自创促单口播。若证据表中没有真实促单句，只能把书名、上市信息、购买提示放在单独标注的封面/结尾卡，不得冒充人物原话。

每条脚本只设一个主要叙事情绪点，例如警醒、心疼、愤怒、释然、希望。使用“提出矛盾 → 补充事实/经历 → 推进情绪 → 给出判断或余味”的逻辑，不按金句热度机械拼接。

允许：

- 重排不同视频中的完整句段；
- 删除口头重复、语气词和不影响原意的旁枝；
- 在两段之间使用画面停顿或非口播文字卡。

禁止：

- 改写人物原话、拼接半句话改变原意；
- 用 AI 合成新口播冒充原说话者；
- 为了营销强行加入素材中不存在的观点；
- 重复使用同一句作为多条脚本的核心，除非用户明确要求。

## 2. 脚本表格

每条脚本至少包含：

| 输出时间线 | 逐字原话 | 源视频时间码 | 视频链接 | 视频 ID/本地素材 | 片段作用 |
| --- | --- | --- | --- | --- | --- |

先完成“源视频时间码”，再根据片段时长计算“输出时间线”。相邻片段若来自同一视频且时间重叠，剪辑清单中只保留一次，避免重复说词。

脚本完成后做三项检查：

1. 单独朗读是否形成完整逻辑；
2. 删掉任何一段后，哪条因果或情绪链会断裂；
3. 每句话能否在证据表中找到完全对应的链接和时间码。

## 3. EDL JSON

`scripts/build_roughcut.py` 接受如下结构：

```json
{
  "title": "脚本标题",
  "segments": [
    {
      "source_path": "/absolute/path/video.mp4",
      "start": "00:00:28.000",
      "end": "00:00:42.000",
      "quote": "逐字原话",
      "source_url": "https://..."
    }
  ]
}
```

`source_path`、`start`、`end` 为必需字段；其余字段用于追溯。时间码以源视频为准。不要把报告里的估计输出时间误当作源时间。

运行：

```bash
python scripts/build_roughcut.py script-1.json script-1.mp4
```

脚本会验证素材、时长、音视频流，并将画面等比缩放后加边到 1080×1920，使用硬切合并，输出 H.264/AAC。

## 4. 默认粗剪规则

- 竖屏 9:16，1080×1920，30 帧。
- 保留原声和原画面已有字幕；默认不二次烧录字幕。
- 默认不用背景音乐、转场特效、调色或 AI 补帧。
- 不裁掉原视频顶部标题、底部字幕、人物姓名或必要声明；优先等比缩放加边。
- 只做硬切。若句首/句尾被截断，回看源素材微调 0.1–0.5 秒。
- 多源素材响度差异明显时再做响度统一，不把所有视频无条件重复转码多次。

## 5. 成片验收

每条 MP4 检查：

1. 首句与脚本一致，特别核对用户指定的开场调序。
2. 所有片段顺序、文案与时间码一致，没有重复或漏句。
3. 使用 ffprobe 确认 1080×1920、H.264、AAC、音轨存在、总时长合理。
4. 每 10–15 秒抽帧生成接触表，检查标题和字幕未被裁切。
5. 用静音检测查找非预期的长静音；正常停顿不必删除。
6. 抽查每个切点前后 1 秒。发现截字时只调整该切点，不重做全流程。

粗剪用于判断叙事与节奏，不等同于可投放终版。交付时明确哪些包装尚未加入，如封面、书卡、音乐、统一字幕和平台安全区适配。
